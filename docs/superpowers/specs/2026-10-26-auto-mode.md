# F1 – auto mode och den laddade plugin-mappen (2026-10-26)

Utkast till `docs/superpowers/specs/2026-10-26-auto-mode.md`; committas i första sessionen efter bytet, tillsammans med `.claude/hooks/mirror.sh`, `tools/dev/bootstrap.sh`, `tools/dev/watch.sh`, README:s "Developing" och `.gitignore`.

## Rotorsak

`~/.claude/settings.json` laddade repot självt som plugin (`CLAUDE_CODE_PLUGIN_DIRS = ~/solar-clawd`). Claude Code räknar en laddad plugin-mapp som skyddad sökväg (docs: permission-modes, "A directory you loaded with `--plugin-dir`, because Claude Code reloads and runs a mod's code from it when a file changes"). I auto mode skickas skyddade skrivningar till serverklassificeraren, som hoppar över dem: `The server-side auto mode classifier gave no verdict (it skipped this action)`, `reasonCode classifier:auto-mode:unavailable`, och sessionen lämnar auto mode. Sex gånger 25 okt, fyra gånger 26 okt (Claude Code 2.1.310), på `.ts`, `.mjs` och `.md` lika. `permissions.allow` hjälper inte (docs). Uppströms: anthropics/claude-code#95982. Bash-skrivningar in i mappen stoppas också: ett heredoc som skulle lägga skripten i repot nekades av klassificeraren som `[Auto-Mode Bypass]` den 26 okt.

## Lösning

Klonen `~/solar-clawd` är cwd och laddas inte längre. Motorn laddar spegeln `~/solar-clawd-live`, som bara innehåller det motorn läser (`.claude-plugin/` utom `types`, `hooks/`, `assets/`, `types/`, `tsconfig.json`) så att inga andra sparningar laddar om modden. Spegeln hålls i synk av `.claude/hooks/mirror.sh` (under `.claude/`, självt skyddat, så inget som sessionen kan skriva om oombedd körs efter dess verktygsanrop), anropat av:

- `PostToolUse` och `PostToolUseFailure` i `.claude/settings.local.json`, matcher `Edit|Write|NotebookEdit|Bash`, kommandot med spegelsökvägen inbakad;
- git-hooks i `.git/hooks`: `post-checkout`, `post-merge`, `post-rewrite`, `post-index-change` (det sista täcker `stash`, `reset`, `revert`, `cherry-pick`);
- `tools/dev/watch.sh` (fswatch) för sparningar från en editor, valfritt.

Motorn skriver `.claude-plugin/types/` i spegeln; klonen har en symlänk dit så `tsc -p .` fungerar. `.gitignore` ignorerar `.claude-plugin/types` utan avslutande snedstreck (ett mönster med snedstreck matchar bara en katalog, inte länken). Skriptet tar ett lås (`$TMPDIR/solar-clawd-mirror.lock`) eftersom parallella verktygsanrop kör hooken samtidigt, och avstår i en worktree (vars `.git` är en fil).

`tools/dev/bootstrap.sh` gör bytet och körs av personen själv, aldrig genom Claude i auto mode: första spegling, typerna över till spegeln + symlänk, git-hooks, `CLAUDE_CODE_PLUGIN_DIRS` → spegeln (absolut sökväg), hooks i `.claude/settings.local.json`. Idempotent; sparar `.bak-<tid>` av varje ändrad inställningsfil. `autoMode.environment` lämnas orörd (ingen `"$defaults"`-splitsning: listan skrevs av `/auto-mode-setup`, som avsiktligt stavar ut standardvärdena; och ingen rad om betrodd repo: den skulle göra klassificeraren mer tillåtande kring just modd-koden).

## Avvägningen, och säkringen

Skyddet av laddade plugin-mappar finns för att kod som motorn kör inte ska ändras utan att någon läst den. En spegel som kopierar efter varje verktygsanrop skulle upphäva det: en manipulerad Claude (t.ex. via injicerat innehåll på en webbsida) kunde skriva elak modd-kod som körs direkt med motorns rättigheter (`$.process.run`, `$.fs`, `$.http`). Den automatiska säkerhetsgranskningen flaggade detta (HIGH, "permission bypass"). Säkringen: hookarna kopierar efter Claudes egna anrop (settings-hookarna, och git kört från Claudes skal där `CLAUDECODE` är satt) **bara medan personen armerat spegeln** med `tools/dev/arm.sh` (stämpel i `~/Library/Application Support/solar-clawd/dev/mirror-armed`, standard 8 timmar, `off` tar bort den). Personens egna git-kommandon och `watch.sh` kopierar alltid. Oarmerad med något att kopiera säger hooken till en gång i timmen (exit 1 → en hook-notis). Armeringen är alltså ett uttryckligt, tidsbegränsat beslut per arbetspass, i klass med att välja `acceptEdits`, i stället för en stående kringgång. Vill man ha den helt manuell: armera aldrig och kör `.claude/hooks/mirror.sh` själv när ändringarna ska ut.

## Verifierat i sandlåda (kopia av klonen, egen HOME och CLAUDE_CONFIG_DIR)

Första och andra körningen, `git switch` mellan `main` och `ljus-himmel` följer med, `stash`/`pop`/`checkout --` följer med, `--delete` tar bort gammalt i `hooks/` men lämnar motorns `types`, en README-ändring rör inte spegeln, fyra parallella körningar lämnar inget lås, `tsc -p .` via symlänken avslutar 0, `claude plugin test .` 99/99.

## Återstår för personen

1. Kör `install.sh` (kopierar filerna till klonen och kör bootstrapen).
2. Ny Claude-session i `~/solar-clawd` i auto mode: be om en trivial ändring; den ska gå igenom utan att auto mode stängs av. Oarmerad når den inte spegeln (en notis säger det); efter `! tools/dev/arm.sh` når nästa ändring spegeln inom någon sekund (`ls -l ~/solar-clawd-live/hooks/glsl/common.ts`); himlen fortsätter visas.
3. Committa F1-filerna i den sessionen (`.claude/hooks/mirror.sh`, `tools/dev/`, README, `.gitignore`, denna spec).
4. Faller 2: alternativ B (mapp-marketplace + `/reload-plugins`) eller C (`CLAUDE_CODE_AUTO_MODE_SERVER=0`), enligt arbetsplanen.
